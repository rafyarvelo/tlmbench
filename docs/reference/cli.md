## tlmbench

```
TelemetryBench on the command line

Usage: tlmbench <COMMAND>

Commands:
  plugins   The plugins found in your plugins folder and the --config folders, with tier, version and whether they loaded
  info      Channels, units, types, sample count, time range, time source and gaps of each file
  inspect   What a CSV file's import dialog would show: its columns as detected, the first rows, the time column and rate, and the saved import profile for its header (JSON)
  derive    Evaluate one expression over a recording, given as `--expr "sqrt(accel_x^2 + accel_y^2)"` (no name): a series as CSV (time_ns, value) on stdout, or one number
  cache     Build, list or clear the cache (pyramids, gap indexes and CSV columns)
  query     Read a view, values at a time, or exact stats from a recording
  convert   Write recordings as CSV, Parquet, Arrow IPC, HDF5 or MAT v7.3: one file per input in --out, plus <name>.channels.csv
  export    Export a view to a static folder that opens from any static host
  check     Run check sets on recordings and report: exit 0 all pass, 1 a check failed, 2 a file or check couldn't run, 3 a configuration error (the highest applies)
  validate  Lint a `.tlmbench/` folder (the nearest one above the current directory by default): every file that doesn't read, and recipes and checks whose expressions don't parse. Exit 0 clean, 3 problems
  config    Work with the shared configuration
  record    Record a live source into a new session folder until it ends (or --seconds pass); prints its stream health
  help      Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version
```

### tlmbench plugins

```
The plugins found in your plugins folder and the --config folders, with tier, version and whether they loaded

Usage: tlmbench plugins [OPTIONS] [FILE]

Arguments:
  [FILE]  The file to decode with --check

Options:
      --json                            JSON instead of a table
      --check <CHECK>                   Try one plugin (a `.wasm` file) instead of listing: what it says about itself and, with a file, what it decodes (schema, samples, time range) or why it can't. For writing a plugin
      --descriptor <DESCRIPTOR>         Format descriptor (TOML) for fixed-width files without one
      --type <PART>                     The packet type to read, for a packet file with several (default: all in `info` and `convert`)
      --profile <PROFILE>               Import profile (JSON from the app cache, or TOML from `.tlmbench/profiles/`) for CSV files: names, units, types, the time column and the rate
      --cache <CACHE>                   Cache folder (default: $TLMBENCH_CACHE, else the OS cache dir)
      --config <CONFIG>                 A `.tlmbench/` folder to read the shared configuration from instead of the nearest one above each input (repeat; later ones win): recipes, check sets, decoders and import profiles
      --derived                         Add the derived channels of the recipes marked automatic (from --recipes, else the nearest `.tlmbench/recipes` above the file) as channels of the recording
      --recipes <RECIPES>               A recipe file (TOML) or a folder of them (repeat; later ones win a name)
      --expr <EXPRS>                    A derived channel of this one expression, `name=expression` (repeat), as channels of the recording
      --plugins <PLUGINS>               Your plugins folder (default: `plugins/` in the app's data folder). WASM decoders and alignment plugins in it, and in the `plugins/` of each --config folder, are loaded
      --native-plugin <NATIVE_PLUGINS>  Turn on a native plugin of your plugins folder, by file name (repeat). Native plugins run with your rights, so each stays off until named
  -h, --help                            Print help
```

### tlmbench convert

```
Write recordings as CSV, Parquet, Arrow IPC, HDF5 or MAT v7.3: one file per input in --out, plus <name>.channels.csv

Usage: tlmbench convert [OPTIONS] --to <TO> --out <OUT> <FILES>...

Arguments:
  <FILES>...
          

Options:
      --to <TO>
          Output format

          Possible values:
          - csv
          - parquet
          - arrow
          - hdf5
          - mat:     MAT v7.3 (HDF5 underneath; opens in MATLAB with `load`)

      --out <OUT>
          Folder for the output files (created if missing)

  -c, --channels <CHANNELS>
          Channels by name, `*` matching any text (repeat, or separate with commas; default: all)

      --from <FROM>
          Start: an ISO 8601 time, or seconds from the first sample (default: the first sample)

      --until <UNTIL>
          End, exclusive, as for --from (default: after the last sample)

      --resample <RESAMPLE>
          One row per step of this rate instead of per sample (`100Hz`, `2kHz`, or a number in Hz); each channel holds its last value

      --layout <LAYOUT>
          wide: a column per channel; long (CSV, Parquet, Arrow): one row per sample and channel
          
          [default: wide]
          [possible values: wide, long]

      --time <TIME>
          How times are written (auto: exact; seconds for relative times, ISO 8601 for dates in CSV, nanoseconds in Parquet and Arrow)
          
          [default: auto]
          [possible values: auto, seconds, iso, ns]

      --raw
          Stored values in their own type, without scale and offset

      --delimiter <DELIMITER>
```

### tlmbench record

```
Record a live source into a new session folder until it ends (or --seconds pass); prints its stream health

Usage: tlmbench record [OPTIONS] <ENDPOINT>

Arguments:
  <ENDPOINT>  tcp://host:port (connects to it), udp://host:port (listens on it), serial://port?baud=rate (a serial port, 115200 baud when not given), or file:///path (follows a growing CSV or .tlm from its start; only read)

Options:
      --descriptor <DESCRIPTOR>  The frames' format descriptor (TOML); sockets and serial ports need one, files bring their own
      --out <OUT>                Where the session folder goes (default: $TLMBENCH_RECORDINGS, else the app's Recordings folder)
      --seconds <SECONDS>        Stop after this many seconds
      --idle-end <IDLE_END>      UDP: stop once no datagram has come for this many seconds; a file: once it hasn't grown for that long
      --ring-mb <RING_MB>        The ring buffer's size in MB (default: about 10 s of the descriptor's rate)
      --reconnect                TCP and serial: connect again whenever the link drops, until stopped (frames sent meanwhile are lost)
      --json                     The result as one JSON object
  -h, --help                     Print help
```
