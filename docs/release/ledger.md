# Ledger: every v1 requirement and the evidence for it

Written in review R1 (Nov 11, 2026, `main` at `d45727c`) and kept current by every step since (last checked Nov 15). One row per requirement: each bullet and "Done when" sentence of the
roadmap's steps 4.1 to 5.10 (`S<step>-NN`), each Accepted or Modified design decision (or plain promise in the design's
text) that no roadmap row covers (`D-<section>-NN`), each accepted difference (`A-NN`), and what only a real window
shows (`X-win-NN`). IDs are stable: later steps cite them and never renumber. `ci/ledger_check.py` checks this file.

Counts: **Done** 318 · **Partial** 11 · **Missing** 5 · **Diverged** 2 · **Unverified** 25 · **Owner pass** 17 (378 rows).

How to read the evidence. A row added or moved after R1 says the date its evidence was run. Otherwise a test named here was run in the review and passed on Nov 11, 2026 (macOS, M1): the Rust
tests with `cargo nextest run --workspace --no-fail-fast` (269 passed, 1 skipped), the app's UI tests one at a time
with `node tests/t_x.js` from `app/ui` (89 of 89 passed, none rerun, none skipped), the prototype's with
`just proto-test` (29 of 29). `t_x` is a test in `app/ui/tests/`; `proto:t_x` is the prototype's. Rust tests are named
`crate::module::function`. Verdicts: **Done** (the evidence covers the whole sentence), **Partial** (say which part is
missing), **Missing** (no code, or no way to reach it), **Diverged** (built differently from the design or prototype, with no
accepted difference), **Unverified** (may be true; nothing re-runnable shows it), **Owner pass** (needs eyes on a real
window; say what to look at). A budget is Done only with a measurement on the release build. The last column names the step
of `docs/release/release-plan.md` that closes the gap. This ledger is the only feature status: the plan's status table says
where each step stands, and nothing else records either.
